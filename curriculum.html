Clean Code to Scale

A 20-hour curriculum that takes an engineering team from disciplined line-by-line habits through architectural boundaries, deliberate refactoring, distributed-systems tradeoffs, and working effectively alongside AI coding agents.

Overview

Who it's for

  • Software engineers with 1–2+ years writing production code
  • Comfortable in at least one OO or multi-paradigm language
  • Has touched a codebase they didn't design and felt the pain of it

By the end, participants can

  • Name a code smell and apply the matching refactoring safely
  • Draw and defend a dependency-rule diagram for a real service
  • Reason about a system's scaling limits before it hits them
  • Brief, review, and correct an AI coding agent like a junior pair

03

Running it

Cadence

Ten consecutive working days at 2 hours/day fits well as a morning or end-of-day slot. Compressing to 2 sessions/day (4h) across 5 days works too — keep same-module sessions (e.g. 4&5, 9&10) on the same or adjacent days so context doesn't go cold.

Group size & format

6–12 participants, paired for every hands-on block. Works in person or remote; remote sessions need breakout rooms and a shared repo per pair, set up before Day 1.

Tools & prerequisites

  • Team's real codebase(s), or a seeded practice repo per language
  • A test runner already wired up — refactoring days assume green tests
  • An AI coding agent with repo access, configured before Day 8

Assessment

No exam. Progress shows in the artifacts each session produces — the smell checklist, the port interface, the capacity plan, the resilience checklist — which converge on the Day 8 capstone as a single reviewed piece of work — with two architecture sessions still to come.
